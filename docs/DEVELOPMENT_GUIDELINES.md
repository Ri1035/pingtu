# 开发准则（Development Guidelines）

> 本项目（pingtu）所有开发必须遵守以下准则。开工前请先通读本文件。

## 1. 开工前调研

- 先检索开源方案、免费资源、现有 skills 或提示词，避免闭门造车、浪费时间和 token。
- 结论应沉淀到文档（如 HANDOVER / README 的参考项目表），便于复查。

## 2. 范围控制

- **一次只完成指定任务**，不擅自扩展范围。
- **不改动任务之外的文件**。

## 3. 代码规范

- 命名语义化、格式统一。
- **密钥、token、API 地址一律走环境变量**，绝不硬编码进代码，也绝不写进提交信息。

## 4. 署名与水印

- **去除一切 AI 水印及 agent 独有水印**（代码、注释、提交信息、产物中均不得出现）。

## 5. 凭据管理

- GitHub 与 Cloudflare 的 token 可记住并存放本地，但：
  - 不得泄露给外界；
  - 不得提交进仓库；
  - 手动打包的文件中不得包含 token。
- 开发阶段无需就凭据问题反复询问。
- 本地凭据存放位置（仓库之外，已被本文件所在仓库天然隔离）：
  `/workspace/.secrets/pingtu.env`（权限 `600`，见第 8 节说明）。
- 公开邮箱（可对外）：`koka2996978242@outlook.com`。

## 6. 自验证与报告

- 每次完成后**自验证并报告**：本地构建（`npm run build`）、lint、相关测试通过。
- 不得跳过验证，不得假装完成。

## 7. Git 与版本管理

- 规范提交、**小步提交**，做好版本管理与日志记录。
- 提交前确认**提交者邮箱为本人邮箱**，且与所用 GitHub token 对应。
- 发版时同步更新三处：`package.json` 的 `version`、`src/i18n.ts` 的 `appVersion`、`CHANGELOG.md` 归档。

## 8. 部署

- 项目经 **GitHub** 管理、**Cloudflare Pages** 部署。
- 构建命令 `npm run build`，产物目录 `dist`，合入 `main` 后可直接部署。

## 9. 文档组织

- **README 只做项目介绍**，不放核心信息。
- 重要文件建立下沉文件夹归类存放（如 `docs/`）。

## 10. 不确定就问

- 有不确定的地方**先问**，禁止臆造功能、跳过验证或假装完成。
